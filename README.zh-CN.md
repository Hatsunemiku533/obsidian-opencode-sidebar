# OpenCode Sidebar

把 OpenCode 原生网页嵌入 Obsidian 桌面侧栏。非官方插件，不属于 Obsidian 或 OpenCode 团队。

## 安装与多仓库使用

目前发布在 GitHub，**尚未提交 Obsidian 社区插件市场**。

- 方便更新的方式：在每个 vault 安装社区插件 BRAT，然后添加 `Hatsunemiku533/obsidian-opencode-sidebar`。
- 手动方式：从 GitHub Releases 下载 `main.js`、`manifest.json`、`styles.css`，放入该 vault 的 `.obsidian/plugins/opencode-sidebar/`，重新加载 Obsidian 后启用。
- 每个 vault 都需要安装一次。BRAT 可以从 GitHub 更新，不必每次让 AI 复制代码；Obsidian 本身并没有全局插件安装功能。

## 配置

1. 先独立启动 OpenCode Web。本插件不负责启动服务。
2. 在插件设置填入服务地址，默认 `http://127.0.0.1:4096`，也支持远程 HTTP/HTTPS 地址。
3. 无认证服务保持 Basic Auth 关闭；需要认证则开启，填用户名和密码。
4. 可填项目目录，用于筛选顶栏“选择会话”的列表。必须是 **OpenCode 服务端的绝对路径**；远程服务不能直接照填本机路径。
5. 点击“应用”重新连接，再用终端图标或命令面板打开侧栏。

设置按 vault 的完整路径区分，同名不同路径不会混淆。移动 vault 后需要重新配置。
项目目录只筛选插件会话选择器，不会限制原生网页中的所有项目。顶栏标题会在原生网页切换会话时跟随更新。
原生网页首页依其自己“已打开的项目目录”展示会话；如果会话在子目录，首页看不到它，并不意味着数据丢失。可用顶栏“选择会话”直接打开该目录中的会话，或在网页里打开相应子目录作为项目，让首页列出它们。

### 记住项目目录

“记住项目目录”默认开启。每个 vault 分别保存原生网页已添加的项目、展开状态和首页最后选中的目录；刷新或关闭再打开侧栏时，在网页启动前恢复，不自动进入旧会话。不把插件会话选择器的“项目目录”强行设成网页项目。
首次启用后，需要在网页里添加、选中一次自己的项目，之后自动记忆。切换项目后保存新选择，关闭项目后不会下次又被恢复。关闭开关会清除当前 vault 的目录记忆并停止保存，下次重建侧栏仍是空白项目列表；不会立即刷新当前页面或删除服务端项目、会话。
记忆按完整 vault 路径、服务地址和认证身份隔离；更换这些信息后不沿用旧记忆。同一 vault 的多个窗口以最后发生并保存的项目选择变化为准，其他设置的保存不会用旧目录记录覆盖新记录。
只保存目录路径与选择状态，不额外保存原生服务器凭据、会话标签或草稿。记录保存在插件 `data.json` 中，不要公开这个本地文件。启动时通过 guest 网页调试接口注册同源主框架脚本，不使用被 Obsidian 移除的 `preload`，也不生成临时目录脚本文件。检查恢复成功后移除脚本并解除调试连接，再开始保存；恢复失败时保留原记录并显示诊断警告。最多保存 50 个项目，优先保留当前选中项目与最近项目。此适配已核对 OpenCode Web 1.18.18 的原生存储格式；上游格式变化可能需要更新插件。

## 侧栏外观与 TUI

插件工具栏、状态栏和会话选择器使用北欧雾灰蓝配色、中文标签和紧凑图标。设置中的“北欧蓝网页外观”默认开启，在嵌入页浅色模式覆盖背景、文字、图标和边框颜色，并加入中等圆角和平滑过渡动画（系统开启“减少动画”时不播放）；原生深色模式的配色保留。开关即时生效，关闭便移除覆盖层、恢复原生外观，无需刷新对话，不丢草稿。
正文字体和字号可在顶栏 Aa 按钮或设置里的“正文字体”“正文字号”选择：清晰（微软雅黑，默认）、柔和（思源黑体）、书卷（思源宋体），字号 13–17px，默认 14px。只能使用本机已安装的字体；代码与公式保持原字体。无论外观开关是否开启，都会让粗体清楚显示，并把段落内的单个换行显示为换行（与 Obsidian 一致，复制的原文不变）。
不改布局、代码语法或 diff 主题。这些样式不会修改其他 Obsidian 标签页、独立浏览器或手机中的 OpenCode，也不会改变首页会话筛选。

更多菜单里的“打开 OpenCode TUI”在 Windows 本机启动脚本，不下载软件、不启动 OpenCode Web 服务。项目目录下有 `启动opencode-TUI.bat` 时可直接使用；否则在插件设置填写本机 `.bat` / `.cmd` 绝对路径。远程服务器不会自动映射到本机脚本。脚本可能启动程序，请只使用自己信任的脚本。
启动结果只确认外层命令打开了脚本；TUI 是否连接成功请看终端窗口，不以进程创建成功冒充服务连接成功。未找到脚本或启动命令失败会明确提示。

## 披露说明

- **网络：** 只连接你配置的 OpenCode Web 地址；点击阅读按钮时才在浏览器打开阅读服务地址（默认 `http://127.0.0.1:18924`，是本机地址）。无遥测。
- **写入的文件：** 每个 vault 的诊断日志位于系统临时目录 `opencode-sidebar` 子目录（Windows 为 `%TEMP%\opencode-sidebar\`），以及插件自己的 `data.json`。
- **运行本机程序：** 仅在点击“打开 OpenCode TUI”时运行你配置的 `.bat`/`.cmd` 脚本，请只用可信脚本。
- **凭据：** 可选的 Basic Auth 密码以明文保存在 `data.json`。
- **仅桌面端：** 依赖 Electron webview，手机不可用。

## 认证与隐私

- 密码保存在插件 `data.json` 中，**是明文，不是加密**。不要上传这个文件，也不要交给不可信的同步服务。
- 远程访问使用 HTTPS，Basic Auth 的 Base64 本身不能防窃听。
- 密码只加入配置服务对应来源和路径的请求头，不写入 URL，不发送给其他网站。
- 插件没有遥测，也不读取 OpenCode 数据库；只有主动点击“打开 OpenCode TUI”才会通过本机脚本启动终端。嵌入聊天不依赖 18924；阅读按钮需要独立运行的阅读服务。
- 每个活动侧栏使用隔离的临时浏览器分区，避免多 vault/多窗口认证冲突。项目目录可通过上述开关单独记忆；其他网页本地偏好和未发送草稿在关闭或重建侧栏后不保留，已保存的服务端对话不受影响。
- 只连接可信 OpenCode 服务，模型工具权限仍由 OpenCode 控制。

## 阅读页按钮

顶栏书本图标沿用原来的阅读方式：在浏览器打开当前会话的 `/read/<会话ID>` 页面。
如果网页还没进入具体会话，则弹出会话选择器；不会创建或覆盖快照笔记。
默认服务地址是 `http://127.0.0.1:18924`，与原本机配置一致。
可以在插件设置的“阅读服务地址”修改成其他部署地址，每个 vault 独立保存。

18924 阅读服务必须自行启动，并且能读取同一批 OpenCode 对话。
这不是 OpenCode 自带接口，插件不会替用户安装后端，也不会向阅读服务转发 OpenCode 的认证密码。
阅读服务未运行只影响阅读按钮，不影响侧栏聊天。

## 公式复制

在模型回复中拖选文字后正常复制，会转换为 Markdown 纯文本。
行内公式还原成 `$...$`，块公式还原成 `$$...$$`，保留常用段落、列表和代码格式。
普通表格转换为 Markdown 表格，保留表头、行列、列对齐和单元格里的行内格式；竖线转义，单元格换行转换为 `<br>`。只选表格的一部分时保留所选文字，跨单元格的选区仍输出表格；未选表头时添加空表头，单独选一个单元格则只复制该单元格。
从公式中间开始选择时，会复制该公式的完整源码一次，避免丢失或重复。
富文本 HTML 会清除，防止 Obsidian 粘贴出 KaTeX 的视觉文本。
输入框、编辑器中的复制不改写；原生网页“复制整条消息”按钮可能绕过选区处理。
合并单元格、嵌套表格或深层嵌套格式不是完整的 Markdown 往返导出，需要自行检查。

## 更新与故障

- 手动替换插件文件后要关闭再开启插件，或重启 Obsidian。
- 服务离线时每十秒检查恢复；认证错误不会无限重试。
- 服务在线不代表网页加载完成。More 菜单恢复了“诊断嵌入页”“复制调试日志”“打开日志文件”，并提供“打开嵌入页开发者工具”。
- 支持反向代理子路径，但代理和 OpenCode 本身必须正确支持该路径下的资源与路由。

## 故障诊断与日志

出问题时先点“诊断嵌入页”，再点“复制调试日志”。复制时也会重新收集当前现场，附带重载前的近期记录。
日志包含插件版本和构建指纹、Obsidian/Electron/Chromium 版本、连接编号与时序、认证开关、网页主文档状态、脚本/样式失败、页面根节点数量、侧栏尺寸以及公式/复制钩子状态。
前端异常记录已知技术类别和脚本行号，而不是只写“页面出错”；不认识的异常可通过嵌入页开发者工具进一步查看。

遇到加载失败、前端异常或重新连接前，会自动保留页面诊断现场。
判断会区分认证失败、服务连接失败、静态资源失败、前端异常、侧栏隐藏和服务在线但页面空白，并给出下一步排查方向。这是依据现场给出的线索，不是未经复现的根因结论。
诊断不会自动重启网页或清缓存，页面检查最多等待四秒，API 检查另有超时。

日志默认位于系统临时目录的 `opencode-sidebar` 子目录，文件名按 vault 完整路径哈希区分。
Windows 通常位于 `%TEMP%\opencode-sidebar\`，用“打开日志文件”直接打开即可。
单个日志约 512 KiB 后轮换，并保留上一份；写磁盘失败时可以复制内存记录。系统清理临时文件会删除日志，因此不是长期备份。
同一 vault 的多个窗口可共写该文件，排查时按连接编号区分事件。
日志轮换有跨窗口锁，写入失败期间的内存记录也会合并进复制结果，不会因旧文件还存在而漏掉。
极少数崩溃可能遗留 `<日志文件名>.rotation.lock`；关闭使用该 vault 的窗口后只移除锁文件，不删除日志。
近期前端异常提示一分钟后过期，页面恢复后不会一直因为旧异常被判成整页故障。

不记录密码、完整 URL、会话 ID、正文、HTML、请求/响应内容或认证头；任意错误消息只保留技术摘要。
过滤 ResizeObserver 噪声，并限制同类异常的重复记录，避免再出现日志/通知洪水。
日志只留本地，分享前仍应检查；开发者工具可能显示完整请求和正文，不要未经检查直接发到公开 issue。

初始验证环境为 Windows、Obsidian 1.12.7、OpenCode Web 1.18.17，其他平台和版本尚未实测。
